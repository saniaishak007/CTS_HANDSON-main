# Page Object Model (POM) Maintenance Benefit

## Problem in a Flat (Non-POM) Script

In a flat (non-POM) automation framework, Selenium locators are written directly inside the test scripts. If the Submit button's ID changes from `submit` to `btn-submit`, every test script containing that locator must be updated manually. This increases maintenance effort, makes the code harder to manage, and increases the chance of introducing errors.

## How POM Solves This Problem

In the Page Object Model (POM), all locators are stored in dedicated page classes. Test scripts interact only with page methods such as `submit_form()` instead of using `driver.find_element()` directly.

If the Submit button's ID changes, only the locator in the corresponding page class needs to be updated. No changes are required in the test scripts. This makes the automation framework easier to maintain, improves code reusability, and reduces duplication.
